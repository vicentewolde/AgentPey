# Evidencia T125 · anexo técnico para el SEP

Fecha: 2026-10-01. Rama `cc/t125-anexo-sep`. Solo documentación y un test; sin red.

## Entregable

[`ANEXO-SEP.md`](../ANEXO-SEP.md): el recorrido completo, el payment handler
(declaración, configuración resuelta, credencial, chequeos de las dos partes),
el recibo (formato, anclaje, tres checks, extensión UCP), la verificación del
Mandato en cinco pasos, los contratos desplegados con id y wasm, y nueve
brechas para el SEP.

## Criterio: cada formato coincide con el código y con `deployments/`

Cada formato cita su esquema zod por ruta. Lo que puede cambiar sin que nadie
edite el anexo lo comprueba `scripts/fase7-anexo.test.ts`:

```
$ npx vitest run scripts/fase7-anexo.test.ts
 ✓ scripts/fase7-anexo.test.ts (5 tests)
      Tests  5 passed (5)
```

- ids y wasm de `agent-registry`, los dos `policy_rail` y `receipt-registry`;
  contrato y emisor de USDC; URL del facilitator;
- límites de cada rail tal como están desplegados;
- nombre, id, versión, tipo de instrumento y URLs del handler, y nombre y
  esquema de la extensión de recibo; versión de UCP;
- `typ` del recibo (`vitrinee-receipt/0.1`) y del Mandato (`mandate+jwt`);
- los nueve códigos de error del `policy_rail`, leídos de `lib.rs`.

Control negativo: con el id del rail UCP cambiado y `PerDayExceeded` renumerado
en el anexo, el test falla en dos casos; restaurado, pasa.

```
   × names every deployed contract with its id and wasm hash
   × numbers the policy_rail errors as the contract does
      Tests  2 failed | 3 passed (5)
```
