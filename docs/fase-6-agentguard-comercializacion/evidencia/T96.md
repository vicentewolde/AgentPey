## 3. Pregunta 4 del usuario: el asset id, contra el 402 real

```
$ curl -sS "https://stellar-bazaar-x402.vercel.app/api/x402/swap-risk?pair=XLM/USDC&amount=100&side=buy"
HTTP/2 402
{"x402Version":2,"accepts":[{"scheme":"exact","network":"stellar:testnet",
 "payTo":"GDVR2KDK5DSMNYZJKNISUIOBDC6FZK3XZOIQWSS7KL4BRMD5BMW6RMCQ",
 "asset":"CBIELTK6YBZJU5UP2WWQEUCYKLPU6AUNZ2BQ4WWFEIE3USCIHMXQDAMA",
 "amount":"10000","extra":{"inputHash":"WExNL1VTREN8MTAwfGJ1eQ"}}]}
```

**Es el mismo SAC que `venues.json` ya le da a las dos filas.** La advertencia de
`bazaar.ts` es real pero contrasta el bazaar con el **mock** (issuer clásico
`G…`), no con SignalDesk. Verificado contra el 402, no copiado.

Lo que sí es distinto: la cuenta que cobra. `GDVR2KDK…RMCQ` no es
`GB4D4PLL…YOOF` ni la dirección del venue, y el otro recurso cobra a una
tercera. Por eso `payTo` en el grant es una lista de dos.

## 4. Pregunta 3 del usuario: un `amount` en los params no mueve el pago

```
$ curl …"/api/x402/swap-risk?pair=XLM/USDC&amount=100&side=buy"
 "amount":"10000"  ·  "inputHash":"WExNL1VTREN8MTAwfGJ1eQ"

$ curl …"/api/x402/swap-risk?pair=XLM/USDC&amount=999999&side=sell"
 "amount":"10000"  ·  "inputHash":"WExNL1VTREN8OTk5OTk5fHNlbGw"
```

Mismo precio, 10000 stroops = 0,001 USDC, con `amount=100` y con
`amount=999999`. El parámetro queda atado a la factura por `inputHash`; el
precio lo fija el comercio. **No abre un hueco de plata.**

## 5. Hallazgo no previsto: el scriptwriter no se está cobrando

```
$ curl -o /dev/null -w "%{http_code}" ".../api/script?topic=test&durationSeconds=30&tone=dramatic"   → 404
$ curl -o /dev/null -w "%{http_code}" "https://bazaar.browns.studio/api/script?…"                    → 404
$ curl -o /dev/null -w "%{http_code}" ".../api/x402/script?…"                                        → 404
```

Discovery lo anuncia; el comercio no sirve esa ruta en ningún host. De los dos
recursos del bazaar, hoy **sólo `swap-risk-quote` es comprable de verdad**.

## 6. El error que encontró la pantalla, no un test

La primera versión del preflight llenaba los parámetros con valores inventados:

```
$ curl …"/api/x402/swap-risk?pair=probe&amount=1&side=probe"
HTTP 400 {"ok":false,"error":{"code":"INVALID_QUOTE_INPUT",
          "message":"Parámetros inválidos; no se solicita pago."}}
$ curl …"/api/x402/swap-risk?pair=XLM%2FUSDC&amount=1&side=probe"   → 400
$ curl …"/api/x402/swap-risk?pair=probe&amount=1&side=buy"          → 400
$ curl …"/api/x402/swap-risk?pair=XLM%2FUSDC&amount=1&side=buy"     → 402
```

El bazaar valida antes de cotizar, así que una tienda abierta se veía cerrada —
en la pantalla construida justo para distinguirlas. Se vio en el navegador:
las dos tarjetas del bazaar decían "no lo está cobrando".

**La corrección: preguntar por la ruta pelada, sin llenar un solo parámetro.**

```
$ curl -o /dev/null -w "%{http_code}" ".../api/x402/swap-risk"        → 400  (la sirve, validando)
$ curl -o /dev/null -w "%{http_code}" ".../api/script"                → 404  (no la sirve)
$ curl -o /dev/null -w "%{http_code}" ".../api/x402/market-brief"     → 404  (no es del bazaar)
$ curl -o /dev/null -w "%{http_code}" "https://signaldesk.agentpey.com/api/x402/market-brief" → 400
```

Adivinar mejores valores habría sido adivinar por la persona qué quiere comprar.

## 8. La pantalla, corriendo

- `/catalogo` dibuja las dos categorías. Con nada firmado, las cuatro tarjetas
  salen **OUTSIDE THE GRANT**.
- Tras el arreglo del preflight: `swap-risk-quote` sale comprable y
  `ai-video-scriptwriter` sale con "The merchant lists this but is not charging
  for it right now". Es la verdad del despliegue vivo.
- `/catalogo/permiso?producto=swap-risk-quote` muestra la tabla de controles con
  las marcas `SIGNED` / `ON-CHAIN` y el objeto literal de § 7.
- Sin errores de consola. A 375 px, sin desborde horizontal
  (`scrollWidth 375 === innerWidth 375`), cuatro tarjetas.

**No verificado en el navegador, y por qué:** el camino de comprar de verdad
necesita un Mandato firmado, y firmar desde esta instancia local habría creado
un tenant y una sesión de consentimiento **reales en producción**
(`agentpey.com`). Ese camino está cubierto por los 15 tests HTTP de
`catalog-http.test.ts`, que sí recorren firmar → comprar contra un AgentPey
falso.
