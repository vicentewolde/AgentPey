## 4. La tabla, wallet por wallet

Prueba del usuario en `http://localhost:8787/wallet-lab.html`, Chrome 154 en macOS, 6-oct, con las extensiones de
LOBSTR y xBull instaladas y la wallet importada. La primera vez, el selector ofrecía instalar las dos:

- **LOBSTR:** el kit le da a cada wallet 1 s para decir que está; la extensión contesta por mensaje en hasta 2 s, y
  perdía la carrera. Arreglo: se le pregunta una vez al cargar la página (`PatientLobstrModule`).
- **xBull:** el puente del kit usa la extensión solo si la página tiene `window.xBullSDK`; si no, abre la wallet web,
  que no tiene la cuenta. La página de prueba ahora muestra qué extensiones ve.

Después del arreglo, las dos se detectan en `localhost` (`"detected": { freighter: true, xbullExtension: true,
lobstr: true, hana: false }`):

| Wallet | Firma mensaje (SEP-53) | Verifica en el servidor | Firma transacción | Verifica en testnet | Se ofrece en |
|---|---|---|---|---|---|
| xBull (extensión) | sí | sí | sí | **sí** | las cinco pantallas |
| LOBSTR (extensión) | sí | sí | sí | **no** | solo donde no se firma una transacción |
| Freighter (extensión) | sí | sí | sí | **sí** | las cinco pantallas |
| Hana | sin probar | | | | las cinco pantallas, según el kit |

Cuenta usada en las dos: `GCP3LL3O…UKHL`. Informe crudo de xBull: `signsMessage: true, messageVerifies: true,
signsTransaction: true, transactionVerifies: true, errors: {}`. De LOBSTR: lo mismo salvo `transactionVerifies:
false` (`InvalidSignature: the transaction carries no valid signature by that account`).

**Por qué LOBSTR no verifica la transacción:** el kit avisa que LOBSTR no deja que la página elija la red, y la firma
salió sobre otro hash que el de testnet. El laboratorio ahora prueba también contra mainnet, y la segunda corrida del
usuario lo confirmó: `SignedForAnotherNetwork: the wallet signed this transaction for Stellar mainnet, not testnet`.
Freighter, en la misma página, pasó las cuatro columnas ("funciona", 6-oct). **Consecuencia (`R-23`, precisado):** cada pantalla declara qué firma
(`data-needs`), y LOBSTR no se ofrece en `consent.html` ni en `revocar.html`, que firman una transacción de testnet;
sí en la respuesta a una disputa, el portal, el inicio de sesión del MCP y el laboratorio, que solo firman mensajes.
Comprobado en el navegador integrado: `revocar.html` ofrece Freighter, xBull y Hana; el laboratorio, las cuatro.
