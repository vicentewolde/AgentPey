# Evidencia · T156 — El chat de Grok compra por el MCP (`R-37`)

Spec: [T156](../SPEC.md). Decisión: [`R-37`](../DECISIONES.md). Origen: [`T144-agentes.md`](T144-agentes.md) §2 y §4.

## 1. El cambio (14-oct, rama `cc/t156-mcp-grok`)

`apps/mcp/src/oauth/server.ts`:

- `DEFAULT_REDIRECT_URIS` suma una tercera dirección, exacta:
  `https://grok.com/connectors-oauth-exchange-code/`. Se compara como texto completo (`Set.has`), igual que las de
  Claude y ChatGPT: ni por host ni por prefijo.
- Un registro rechazado escribe `oauth registration refused` con las direcciones rechazadas: de cada una, solo esquema,
  host y camino, recortados a 200 caracteres (`loggableRedirectUri`). Si traía usuario y clave, query o fragmento, se
  descartan y se marca `[dropped: …]`. El esquema de registro ya acepta 5 como máximo. Un registro aceptado no escribe
  direcciones.
- El mensaje de `invalid_redirect_uri` nombra a Grok.
- El aviso contra suplantación, en la página (inglés y español) y en el mensaje que firma la wallet, dice ahora
  "from your own Claude, ChatGPT or Grok" (corregido tras `/revisar`). El servidor arma ese mensaje él mismo al pedirlo
  y al aprobar, así que el cambio no rompe una firma en curso más allá de un desafío pedido justo antes del despliegue.
- Sin cambios: la wallet que entra (`MCP_ALLOWED_WALLET`, `R-33`), PKCE, la audiencia del token, las herramientas, el
  rail y sus topes. Los hosts de los que se lee un CIMD siguen saliendo de la lista, así que suman `grok.com`
  (`R-37` §3).

`apps/mcp/README.md`: sección "Connect Grok".

## 2. Tests

Dos tests nuevos en `apps/mcp/src/oauth/oauth.test.ts`:

1. *lets the Grok chat in through its exact callback, and nothing that only looks like it*: Grok se registra, la
   página de inicio de sesión abre, la wallet firma, el código vuelve a la dirección de Grok y se cambia por un token.
   Se rechazan al registrar: sin barra final, `www.`, `http://`, otro camino, `:443` escrito, `:8443`, con query, con
   fragmento, `grok.com.attacker.example`, con `user@` y con mayúsculas. Un cliente de Grok no puede pedir la vuelta
   de Claude, y uno de Claude no puede pedir la de Grok.
2. *logs which redirect URIs a refused registration asked for, cut short, and nothing for an accepted one*.

Agregados tras `/revisar` (sin bloqueantes; siete hallazgos, todos corregidos a pedido del usuario):

3. Las once parecidas también se prueban en `/authorize` con el cliente de Grok: 400 y sin `location`.
4. *trusts exactly Claude's, ChatGPT's and Grok's callbacks, and still registers ChatGPT*: fija la lista completa, para
   que cualquier ampliación rompa un test; la de ChatGPT no tenía test.
5. *reads a client document from grok.com, and still refuses a callback it names that is not trusted*.
6. *keeps only scheme, host and path of a refused callback in the log, and flags what it dropped*.
7. El mensaje firmado y la página nombran a Grok en el aviso.

Primero fallaron los dos (sin el cambio):

```
× ... lets the Grok chat in through its exact callback ... → expected 400 to be 200
× ... logs which redirect URIs a refused registration asked for ... → expected 'this server only sends people back to…' to contain 'Grok'
```


Tras las correcciones de `/revisar`:
