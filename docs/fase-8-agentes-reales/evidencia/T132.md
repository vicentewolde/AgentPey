## 2. Un pago, un recibo

Antes del arreglo, con una plataforma de tienda que tarda 50 ms y dos
solicitudes a la vez con el mismo pago, el test nuevo falló: dos pedidos.

```
× POST /checkout/:productId — idempotency, duplicates, stock > signs one receipt for one settlement even when two requests carry it at once (T132) 73ms
  → expected 'ord_musnaa2q7acb941077' to be 'ord_musnaa2qc1de9268cd' // Object.is equality
```

Después del arreglo en `fulfilPaidPurchase`:

```
$ pnpm --filter @vitrinee/gateway exec vitest run src/checkout.test.ts src/ucp/checkout.test.ts --reporter=verbose
✓ src/checkout.test.ts > POST /checkout/:productId — idempotency, duplicates, stock > signs one receipt for one settlement even when two requests carry it at once (T132)
✓ src/ucp/checkout.test.ts > one settlement backs one receipt (T132) > refuses a second checkout that settles with a transaction another order already used
```

El caso en secuencia ya estaba cubierto ("never creates two orders for one
settlement transaction") y sigue en verde.
